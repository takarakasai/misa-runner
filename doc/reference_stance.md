# 基準姿勢（立ち姿勢）を機体ごとに決められるようにする — 要件

対象: `misa-runner`（機体非依存）。機体側に残るものは §5。
関連: [`handover.md`](handover.md) / `crates/misa-runner/src/robot.rs` の
`kin_at_height` / `base_gait_config`

## 1. 何を解きたいか

**実機で測った姿勢を、歩容の基準姿勢（立ち姿勢）として使いたい。**

きっかけは keel の実測（2026-09-07、`/low_state`）。いまの基準姿勢と並べると
こうなる。数値は base_link 座標の足先で、単位 m:

|  | いまの基準姿勢 | keel の実測姿勢 |
|---|---|---|
| FL | +0.245, +0.196, −0.300 | +0.170, +0.183, −0.352 |
| FR | +0.245, −0.196, −0.300 | +0.189, −0.171, −0.352 |
| RL | −0.245, +0.196, −0.300 | −0.371, +0.179, −0.310 |
| RR | −0.245, −0.196, −0.300 | −0.343, −0.174, −0.312 |
| 前後の高さ差 | 0 | **41 mm（前上がり 4.2°）** |
| 前後スパン | 0.490 | 0.537 |
| 左右幅 | 0.391 | 0.353 |
| 足パターンの中心 | 胴体中心 | **胴体の 89 mm 後ろ** |

**モデルと実機は一致している。** 立ちピッチを 3 通りで出すと、実機の IMU
クォータニオン −4.25°、この関節角＋モデルの順運動学 −4.36°、MuJoCo で物理的に
立たせた結果 −4.24°。**つまりモデルの幾何は信用してよく、足りないのは
「この姿勢を設定として書ける形」だけ。**

## 2. いま表現できること・できないこと

**表現できる**

| | どこ |
|---|---|
| 立ち高さ（4 脚共通のスカラ 1 つ） | `GaitTuning::stance_height_m` → `kin_at_height` |
| 実行中の高さ変更 | `Controller::apply_body_height` → `set_kinematics` |
| 周期・遊脚高さ・歩幅・接地比（実行中も） | `misa_core::GaitTune` / `base_gait_config` |
| 胴体の傾き（足は接地したまま胴体だけ回る） | `Intent::body_attitude_rad` |

**表現できない**

- **脚ごとの足先位置。** `kin_at_height` は 4 脚すべての
  `nominal_foot_body.z` に同じ値を入れ、x と y は
  `control.kinematics_pose` での順運動学のまま。
- 前後の高さ差（＝立ちピッチ）。上の 41 mm がこれ。
- 足パターンの前後オフセット（89 mm）と左右幅（38 mm）。

**歩容ライブラリ側は既に足りている。** `LegKinematics::nominal_foot_body` は
脚ごとの `Vector3<f64>`（`quadruped-gait/src/config.rs`）で、着地点計画は
`lift_off = nominal − half` / `touch_down = nominal + half` とここを基準に
するだけ（`src/footstep.rs`）。**`quadruped-gait` の変更は要らない。**
不足しているのは misa-runner の設定・検証・受け渡しに閉じている。

## 3. 要件（misa-runner に入れる）

### R1 基準姿勢を脚ごとの足先位置で持てる

`stance_height_m` のスカラ 1 つではなく、4 脚それぞれの
`nominal_foot_body`（x, y, z）を決められること。**これが本体で、以下はすべて
その入れ方と確かめ方。**

### R2 基準姿勢の由来を 3 通り選べる

| 由来 | 用途 |
|---|---|
| a. 高さスカラ（現状） | 既定。いまのプロファイルがそのまま動く |
| b. **モデルの名前付きポーズ** | `crouch` / `extend` と同じ枠。関節角で書けるので実機から持ってきやすい |
| c. 明示的な足先座標 | 脚ごとに数値で押さえたいとき |

**b を推す。** 実機から得られるのは関節角であって足先座標ではないし、
`control.kinematics_pose` が既に「名前付きポーズから順運動学で基準を決める」
経路（`resolve_kinematics_posture`）を持っている。**同じ仕組みの上に乗る。**

### R3 実機の観測から基準姿勢を作れる

`/low_state`（または記録）の関節角を、そのままモデルのポーズとして書き出せる
こと。**手で 12 個の数を写す作業を残さない** — 実測を基準姿勢にする話なのに、
そこが手作業だと取り違える。関節名の並びが機体ごとに違う（keel の
`/low_state` は thigh, hip, calf の順）ので、名前で対応付けること。

### R4 左右対称化を明示的な操作として持つ

実測はゲインと重力でつり合った姿勢なので**左右で 2〜3 cm ずれる**（keel の
実測で足先 x が FL/FR 20 mm、RL/RR 28 mm）。そのまま基準にすると左右差ごと
焼き付く。**左右平均を取る操作を用意し、取ったかどうかを記録に残す。**
黙って対称化してはいけない（本当に非対称な機体もある）。

### R5 受け入れ前に検証する

基準姿勢を採用する前に、次を機械的に確かめて**通らなければ起動を止める**か
警告する。

1. **可動域** — 4 脚の角度がモデルの範囲に入っているか
2. **IK 可達** — その足先位置を歩容の IK が解けるか（歩幅・遊脚高さを
   足した最悪点でも）
3. **左右対称性** — 許容差を超えていたら言う（R4 と対）
4. **前後の高さ差** — しきい値を超えたら言う（§4 参照）
5. **膝の向き** — `knee_pattern` と矛盾していないか

### R6 実行中に差し替えられる

既存の `set_kinematics(kin_at_height(h))` の経路に乗せる。**歩容の位相を
壊さないこと**（`set_config` が位相を保つのと同じ扱い）。実行中に基準姿勢を
振って実機で決められるのが目的。

### R7 採用前後を並べて見られる

`check` で採用後の足先座標と立ちピッチを数値で出し、`sim` で**同じカメラで
2 枚描いて並べられる**こと。keel の比較で使った手順（モデルへポーズを足して
物理で立たせ、側面と正面を撮る）を再現可能な形にする。

### R8 プロファイルに書けて、記録に残る

採用した基準姿勢は**プロファイルだけ読めば再現できる**こと。実機で追い込んだ
値がどこにも残らないのがいちばん困る。`check` の出力にも出す。

### R9 既定では挙動が 1 ビットも変わらない

`stance_height_m` だけを書いた既存のプロファイル（namiashi / namiashi2 /
keel）は、出力が完全に同じであること。**回帰テストで固定する。**

## 4. 決めるべきこと（設計の分かれ道）

### 前上がりを「足先の高さ差」で表すか「胴体の姿勢」で表すか

2 つの機構がある。IK 的にはほぼ同じ姿勢になるが、意味が違う。

| | 足先の高さ差（R1） | `body_attitude_rad` に定数 |
|---|---|---|
| 着地点計画の基準 | 傾いた面に沿う | 水平面のまま、胴体だけ回る |
| 実装 | `nominal_foot_body.z` を脚ごとに | 既存機構に定数を足すだけ |
| 歩容中の意味 | 「その面の上を歩く」 | 「水平に歩きながら胴体を傾ける」 |

**前者を推す。** 歩容は `nominal_foot_body` を基準に着地点を作るので、
基準姿勢そのものを動かすほうが素直。後者は姿勢モード（操縦者が振る量）と
競合し、上限 `body_attitude_max_rad` を食う。

### 「胴体は水平」という要件との衝突をどう扱うか

**前後の hip 高さを揃える（前傾・後傾は不可）は、この機体の決めごと。**
keel の実測姿勢はそれを 4.2° 破っている。どうするか 3 択:

1. しきい値を超えたら**拒否**する（安全側。ただし意図的な傾きも書けない）
2. **警告して通す**（`check` と起動ログに出し、記録に残す）
3. プロファイルに「意図した傾き」として明示させ、書いてあれば黙る

**3 を推す。** 「うっかり傾いた」と「傾けたい」を区別できるのはプロファイル
だけで、区別できないと警告が慣れになる。

## 5. 機体側（keel-runner など）に残るもの

- 実測した関節角そのものと、採用するかの判断
- プロファイルの値（基準姿勢、しきい値、意図した傾きの宣言）
- 立ち上げ手順への組み込み（`bringup_checklist_*.md`）
- **keel の場合**: いまの構造で採れるいちばん近い形は「高さだけ 0.30 →
  0.33 m、水平のまま」。前上がり 4.2° と足パターンの 89 mm 後退は R1 が
  入るまで書けない。

## 6. 受け入れ条件（2026-09-10 実装。README「基準姿勢（立ち姿勢）を機体ごとに決める」）

- [x] 既存 3 機のプロファイルで出力が変わらない（R9）— `stance_height_m` だけの由来は
      `kin_at_height` と 1 ビットも違わないことをテストで固定（`a_height_only_stance_is_bit_identical_to_the_old_path`）
- [x] 実機の観測 / 記録から基準姿勢を作り、`check` が通る（R3）— `misa-run stance capture`
      （`--secs` で実機、`--from-record` で記録）。keel の `/low_state` そのものは
      keel-run 経由（Backend）で読む
- [x] 左右対称化の有無で足先座標が期待どおり変わる（R4）— `stance_symmetrize`、
      `--symmetrize`。取ったことがプロファイルに残る
- [x] 可動域外・IK 不可達の基準姿勢が**起動前に**弾かれる（R5）— `load_from_config` が
      `stance_report` のエラーで止まる。左右差・傾きの宣言違いは警告
- [x] 実行中に差し替えても歩容の位相が飛ばない（R6）— `stance_kinematics_at_height` →
      `set_kinematics`（高さ変更と同じ道。MuJoCo で keel の実測姿勢のまま
      `--height-offset -0.03` を入れて歩く）
- [x] 採用前後を並べる（R7）— `check` の数字（足先・高さ・スパン・幅・中心・傾き）と、
      `sim --vx 0 --features render --video --cam-fixed` を 2 プロファイルで撮る手順
- [x] keel の実測姿勢を入れると、`sim` の立ちピッチが −4.24°（実機 IMU −4.25°、
      順運動学 −4.36°、±0.2° 以内）

未実装: `stance_pose`（由来 b）を実機の観測から**モデルのポーズとして**書き出す道。
capture は由来 c（`stance_feet_body`）で書く — 関節角はコマンドが表示するので、
ポーズとして残したければ `.misa` へ写す。keel の実測値は keel-runner の
`robots/keel_stance_measured.toml`。
