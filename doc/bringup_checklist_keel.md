# keel 実機立ち上げチェックリスト

対象: 四脚ロボット **keel**（Robstride ×8 + MyActuator ×4、CAN）
繋ぎ方: **STM ブリッジ経由の ROS 2**（`/low_command_msg` / `/low_state`）
関連: [`bringup_checklist.md`](bringup_checklist.md)（namiashi 版） /
[`../ros/README.md`](../ros/README.md) / `../robots/keel.toml`

作成日: 2026-09-04（シムでの詰めが一段落した時点。**実機はまだ一度も動かして
いない**）

---

## この文書の使い方

**上から 1 段階ずつ、合格条件を満たしてから次へ進む。** 飛ばさない。

| 危険度 | 意味 |
|---|---|
| 🟢 | モータは一切動かない（読み出しのみ） |
| 🟡 | 脱力させて手で動かす |
| 🔴 | 複数軸が同時に動きうる |

### namiashi 版との違い

**段階 4〜6（可動域の実測・符号の確定・ゼロ点の確定）に当たるものが無い。**
keel はゼロ点も可動域も符号も **STM ブリッジが持つ**ので、こちらから校正
する経路が無い。S.BUS も無く、操縦は ROS 2 のトピックとサービス。

**そのぶん「1 軸だけ小さく動かす」段階が作れない。** 🟢 の次がいきなり
12 軸同時の 🔴 になる。段階 2-3（手で動かして符号を見る）を挟んであるのは
それを少しでも埋めるため。**脚を浮かせるまでは絶対に励磁しないこと。**

## 段階 1: 実機に触れない検証【🟢】

### 1-1. 設定とモデル

```sh
./target/release/misa-run check --robot robots/keel.toml
```

**合格条件:**
- [ ] `設定: OK`
- [ ] `関節 23 / nq=16`（脚 12 + 車輪 4）
- [ ] `ポーズ: ["crouch", "extend"]`
- [ ] `MIT ゲイン: kp [...] / kd [...]` が出て、**送るつもりの値と一致**
- [ ] 当たり判定メッシュの警告が **出ない**
- [ ] `IK→モデル符号表` が `[[1, -1, -1] × 4]`（段階 2-3 で実機と突き合わせる）
- [ ] `傾きの報告: 29° 超で ERROR`（`無効` になっていないこと。**keel は接地
      センサが無いので、姿勢角が転倒に近づいたことを知る唯一の手がかり**）
- [ ] 配線が `ROS 2 ブリッジ経由` で、トピックが `/low_command_msg` `/low_state`

**異常時:** メッシュの警告が出たら段階 0-4 へ戻る。`sim` はこの状態では
起動しない（当たり判定の無いリンクができて、衝突しないぶん動いて見える）。

### 1-2. 歩容が可動域と変化率に収まるか

```sh
for g in crawl walk trot; do
  ./target/release/misa-run dump --robot robots/keel.toml --gait $g \
      --vx 0.12 --vy 0.08 --wz 0.4 --secs 10
done
```

**合格条件:**
- [ ] 3 歩容とも `可動域: すべて範囲内`
- [ ] 「歩容が要求する目標の変化率」の表に **`✗` が無い**

**なぜ見るか:** 変化率が上限を超えていると、実機では安全ゲートが目標を
鈍らせて歩容が崩れる。上限は `hardware.max_target_rate_rad_s`（keel は 8.0）と
モデルの定格速度（calf 10.47 / hip・thigh 17.49）の厳しいほう。

### 1-3. シムでの到達点（参考値）

実機の比較対象として控えておく。**シムのゲインは実機とは別物**
（kp 1200 / kv 30 / 刻み 0.5 ms）。

| 指令 | シムの実測 | 期待 |
|---|---|---|
| 静止 | +0.013 m / 回転 +0.1° | 0 |
| 前進 0.12 | +2.011 m | +2.52 m（80%） |
| 後退 0.12 | −2.779 m | −2.52 m（110%） |
| 旋回 +0.5 | +464.7° | +601°（77%） |
| 横 +0.10 | +1.831 m | +2.10 m（87%、前後に −0.708 の連れ） |

pitch は −0.11〜−0.53°。動画は `videos/`。

## 段階 2: ブリッジの往復【🟢 モータは動かない】

> **`bridge` が出す指令は全軸 `Idle` = `kp = kd = torque = 0`。**
> ブリッジは MIT しか持たないので、これが「脱力」の表現そのもの。
> 通電していてもモータは励磁されない。

### 2-1. 環境とブリッジの起動

```sh
source /opt/ros/jazzy/setup.bash
source ~/work/keel/colcon_ws1/install/setup.bash   # low_state_msgs / low_command_msgs
source ros/install/setup.bash                       # misa_msgs
```

- [ ] STM ブリッジのノードが上がっている
- [ ] `ros2 topic list | grep low_` で両トピックが見える
- [ ] `ros2 topic hz /low_state` が想定周期で出る

### 2-2. 往復の確認 ★最初の関門★

```sh
./target/release/misa-run bridge --robot robots/keel.toml --secs 30
```

**合格条件:**
- [ ] `受信` が **100%** に張り付く（落ちるなら QoS かトピック名）
- [ ] `最古[ms]` が `state_timeout_ms`（50）を超えない
- [ ] `異常` が 0
- [ ] 「関節を解決できません」の警告が **出ない**

**異常時:**
- 受信 0% → トピック名と QoS（best_effort / keep_last(1)）
- 一部の軸だけ解決できない → `LowState.joint_names` とモデルの関節名の綴り。
  **黙って 0 のままにはしない実装**なので、名前が警告に出る
- 「reindex」が繰り返し出る → 別ノードが同じトピックへ流していないか
  （シムの検証中に `dummy_low_state_publisher` と衝突した実績がある）

### 2-3. 関節の対応と符号を手で確かめる【🟡 脱力させ、手で動かす】

> **ここを飛ばさない。** ブリッジ側の関節名・並び・符号がこちらの想定と
> 一致している保証は、まだ一度も取れていない。

`bridge` を回したまま、**1 関節ずつ手で動かして**表示角を見る。

- [ ] `FL_thigh_joint` を動かすと FL の腿だけが変わる（他が動かない）
- [ ] 12 関節すべてで、名前と物理位置が一致する
- [ ] **膝を後ろへ畳む向きで calf が負に動く**（`<<` の前提）
- [ ] 腿を後ろへ倒す向きで thigh が正に動く
- [ ] 手を離すと角度がそのまま残る（励磁されていない）

**合わないとき:** 符号が逆なら歩容は鏡像になって逆へ進む。名前が入れ替わって
いれば歩容は成立しない。**どちらもブリッジ側で直す**（こちらには符号を
反転する設定を置いていない）。

### 2-4. 車輪が脱力のままか

- [ ] 車輪 4 軸を手で回せる（歩容は車輪に指令を出さない設計）

## 段階 3: 脚を浮かせて励磁【🔴 12 軸が同時に動く】

> **ここから危険度が上がる。** 脚が浮いていることを再確認してから。
> **前段階までと違い、ここで初めてモータが力を出す。**

### 3-1. 起動して脱力のまま待つ

```sh
./target/release/misa-run run --robot robots/keel.toml
```

- [ ] **脚が浮いている**
- [ ] 電源を即座に切れる位置にいる
- [ ] 起動直後は脱力（`ModeRequest::Relax` が既定）
- [ ] `MIT ゲイン kp ... / kd ...` がログに出て、送るつもりの値と一致
- [ ] 状態を受け取ったら `状態を受け取りました。操縦を受け付けます` が出る

> **状態が来るまでは何をしても立たない。** 読めていない軸の観測は 0 で、
> keel の関節角 0 は脚を伸ばし切った姿勢。そこから立つと危ないので、
> 1 軸でも読めていないうちは脱力のまま止める仕掛けが入っている。

### 3-2. 初期姿勢へ（低いゲインで）

**まず `mit_gains` を柔らかい既定（kp 120 / kd 2.0）のままで。**

```sh
ros2 service call /keel/misa_run/set_mode misa_msgs/srv/SetMode '{mode: 1}'
```

- [ ] 12 軸が **静かに** 目標へ寄る（跳ねない、唸らない）
- [ ] 手で軽く押すと戻る程度の柔らかさ
- [ ] 安全ゲートの警告が出ない（出たら何を丸めたかログに出る）

**止める条件:** 発振する / 異音 / どれか 1 軸でも想定と違う向きへ動く
→ 即 `{mode: 0}`（脱力）か電源断。段階 2-3 へ戻る。

### 3-3. ゲインを上げる

**脚を浮かせたまま**、kp を段階的に上げて追従を見る。
`robots/keel.toml` の `[hardware.mit_gains]` を書き換えて再起動する。

| kp | kd | シムでの静止時の胴体 z（指令 0.300） | 見どころ |
|---|---|---|---|
| 120 | 2.0 | 0.250（沈む。腿と車輪が接地） | 立ち上げ用。**この値では立てない** |
| 200 | 2.0 | 0.297（後輪がまだ触る） | |
| 300 | 3.0 | 0.308（足だけで立つ） | **ここから立つ** |
| 600 | 6.0 | 0.316 | |

- [ ] 各段で発振しない
- [ ] 指令角への寄り方が速くなっていくのが分かる
- [ ] 300 まで上げても異音・過熱が無い

**根拠:** 立ち姿勢で膝に要るトルクは 53 kg ÷ 4 脚 × モーメント腕 0.151 m
≒ **19.6 N·m**。kp 120 だと 19.6/120 = 0.163 rad（9.4°）の定常偏差が要る。
モータの effort は hip/thigh 96 N·m、calf 180 N·m なので、kp 300 では
0.32 rad の誤差で腿が飽和する。

**止める条件:** 発振（kd を上げる）/ 過熱（`bridge` の温度）/ 異常ビット。

## 段階 4: 接地して静止保持【🔴】

> **初めて自重がかかる。** 落としても壊れない高さから、ゆっくり下ろす。

- [ ] 段階 3-3 で決めたゲイン（**300 以上**）を設定に書いた
- [ ] 落下養生がある

```sh
./target/release/misa-run run --robot robots/keel.toml
ros2 service call /keel/misa_run/set_mode misa_msgs/srv/SetMode '{mode: 1}'
```

**合格条件:**
- [ ] 4 脚で立つ（腿・車輪が接地していない）
- [ ] 胴体が**水平**（前後の hip 高さが揃う）
- [ ] 沈み込みが 1 cm 以内（シムでは指令 0.300 に対し 0.308〜0.316）
- [ ] 手で軽く押しても戻る
- [ ] 5 分放置して過熱しない
- [ ] 傾きの ERROR が出ない

**止める条件:** 沈む（ゲイン不足。段階 3-3 へ）/ 前後に傾く / 特定の脚だけ
潰れる（その脚の追従を `bridge` で見る）。

> **`**胴体が N° 傾いています**` が出たら転倒しかけている。**
> `control.max_tilt_rad`（既定 29°）を超えると ERROR で出るが、
> **自動では脱力しない** — 立っている四足を脱力させると崩れるので、
> 止めるかどうかは operator が決める設計。**出たら手を出せる位置にいること。**

## 段階 6: 歩く【🔴】

> **最初は crawl（接地比 0.85、常に 3 本接地）から。** trot は 2 本しか
> 接地しないので、転ぶときは速い。

### 6-1. crawl でその場足踏み

```sh
ros2 service call /keel/misa_run/set_gait misa_msgs/srv/SetGait '{gait: 0}'
ros2 service call /keel/misa_run/set_mode misa_msgs/srv/SetMode '{mode: 2}'
# 速度は入れない（cmd_vel を出さなければ 0）
```

- [ ] 歩容に入っても足が上がらない（速度 0 なら全脚接地で位相凍結）
- [ ] 胴体が水平のまま

### 6-2. crawl で前進

```sh
ros2 topic pub -r 20 /keel/cmd_vel geometry_msgs/msg/Twist '{linear: {x: 0.05}}'
```

- [ ] **前へ進む**（後退したら膝の向きか符号。段階 2-3 へ）
- [ ] 胴体が水平のまま
- [ ] 安全ゲートが目標を鈍らせていない（警告が出ない）

`cmd_vel` を止めると 300 ms 後に速度が 0 に落ちてその場で立つ
（**モードは変えない**）。

### 6-3. walk → trot

- [ ] walk（`{gait: 1}`）で前進
- [ ] trot（`{gait: 2}`）で前進
- [ ] 後退・横・旋回

**シムとの比較:** 指令の 77〜110%（段階 1-3 の表）。**大きく外れたら
`bridge` で追従誤差を見る。**

## 分かっている穴

| | |
|---|---|
| **接地センサが無い** | ブリッジは `has_contacts: false`。接地推定ができない。転倒に近づいたことは**姿勢角でしか分からない**（`control.max_tilt_rad`、ERROR を出すだけで自動では脱力しない）。**利用者の判断で当面は保留**（2026-09-04） |
| **歩容は開ループ** | センサは姿勢角しか読まず、それも CHAMP では no-op。**CHAMP を使う以上これでよい**（同上） |
| **往復の相関が無い** | `LowState` に指令の連番の反響が無いので、往復遅れを実測できない。観測の古さは受信時刻でしか測れない |
| **🟡 の段階が薄い** | 校正がブリッジ側にあるため、1 軸だけ動かす段階を作れない。段階 2-3 で手で確かめるのが唯一の予行 |
